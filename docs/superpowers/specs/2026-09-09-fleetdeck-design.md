# fleetdeck — дизайн

**Дата:** 2026-09-09. **Статус:** согласован, готов к написанию плана реализации.

## 1. Задача

Управлять флотом фоновых сессий Claude Code из одного локального окна.

Сегодня флот живёт в двух местах: сессии — в демоне Claude Code, доступные через `claude agents` и MCP, а смысл задач — в доске из markdown-карточек, которую человек смотрит через Obsidian. Связка работает, пока сессий две-три. Дальше проявляются три беды:

1. **Сессии ждут ответа, и это не видно вовремя.** Сессия останавливается на вопросе или упирается в лимит и молчит. Зафиксированный случай: три сессии простояли два часа после того, как лимит уже сбросился, потому что никто не заметил остановку.
2. **Теряется контроль над отдельной сессией.** Чтобы понять, что она делает, приходится читать терминальный экран, где содержательный текст перемешан со спиннерами и обрывками перерисовки.
3. **Доска в Obsidian неудобна** для этой работы: она рассчитана на заметки, а не на пульт, и ничего не знает о состоянии сессий.

## 2. Что строим

Два компонента в одном репозитории, отдаваемые вместе как open source.

**Пульт** — сервер на Go со встроенным веб-интерфейсом. Ставится бинарём, поднимается локально, показывает флот и доску, передаёт ввод в сессии, шлёт уведомления.

**Конвенция** — плагин Claude Code, переезжающий из приватного репозитория: скилы `fleet-orchestrator` и `card-keeping`, шаблон доски, валидатор карточек, `transcript_digest.py`.

Компоненты связаны, но не заперты друг в друга: пульт работает и без доски — тогда это просто управление сессиями. Доска добавляет поверх смысл задач.

### 2.1 Границы первой версии

Вырезано намеренно, каждый пункт удваивает объём работы:

- вторая машина, сеть, аутентификация — только `localhost` и unix-сокет;
- полнотекстовый поиск по транскриптам;
- редактор markdown и правка тела карточек;
- Telegram и мобильный доступ;
- любые решения за пользователя: пульт показывает и передаёт, но не решает.

## 3. Три источника правды

Главное правило архитектуры: источники не смешиваются и не подменяют друг друга.

| Источник | Что даёт | Чего от него не ждать |
| --- | --- | --- |
| `control.sock` демона | жизнь сессии: список, состояние, экран, ввод | смысл задачи |
| Транскрипт `jsonl` | что сессия делала: шаги, вопросы, ответы | текущее состояние |
| Файлы доски в git | смысл задачи: стадия, прогресс, лог, связи | что происходит сейчас |

Связывает их **одно поле** `session` в карточке. Состояние сессии в карточку не дублируется никогда: оно живёт в демоне и показывается оттуда.

Отсюда правило для интерфейса: читаемая выжимка берётся из транскрипта, живой экран — из сокета. Это разные источники, и путать их нельзя. Попытка строить выжимку по экрану даёт нечитаемую кашу.

### 3.1 Протокол демона

Демон слушает unix-сокет `/tmp/cc-daemon-<uid>/<id>/control.sock` и говорит JSON. Всё, что описано ниже, снято с живого демона версии 2.1.263, а не выведено из документации: первая редакция этого раздела перечисляла имена тулов MCP `claude-agents` и выдавала их за команды сокета, что неверно. MCP — отдельный слой поверх демона, и его словарь с протоколом не совпадает.

Запрос — ровно одна строка JSON с переводом строки в конце. Демон читает байты до первого `\n`, эта строка и есть запрос, всё после неё считается хвостом полезной нагрузки. Первая строка длиннее 1 МБ отвергается кодом `ETOOLARGE`; соединение, не приславшее данных, рвётся через 30 секунд. Конверт обязателен: `{"proto":<int>,"op":"<name>"}`, где `proto` — целое, равное протоколу демона.

Операции: `ping`, `list`, `has`, `attach`, `reply`, `dispatch`, `nudge`, `yield`, `lease`, `leases`, `await-ack`, `kill`, `respawn-stale`, `resize`, `shutdown`. Пульту нужны четыре: `list` — список сессий, `attach` — экран, `reply` — ввод в сессию, `ping` — живость.

`ping` отвечает `{"ok":true,"op":"ping","version":"...","proto":1}` и ключа не требует. Отсюда берётся `proto` для последующих запросов — константу в коде не хардкодить: демон обновится, а пульт будет молча получать `EPROTO` вместо внятного отказа.

Запись требует аутентификации. `reply` и `dispatch` без предъявленного control key отвечают `{"ok":false,"code":"EAUTH"}`. Ключ лежит в `~/.claude/daemon/control.key`, права 0600, каталог 0700, содержимое — 32 hex-символа, читается как UTF-8 с обрезкой пробелов. Никаких привилегий сверх обычных прав пользователя не нужно: пульт работает под тем же пользователем, что и демон. Поверх ключа демон проверяет uid пира и чужому отвечает `EPEERUID` ещё до разбора запроса — это и есть настоящая граница безопасности, а ключ защищает от чужого процесса под тем же пользователем.

Состав полей записи сессии, какой отдаёт `list`, и ничего сверх: `agent`, `attempt`, `backend`, `cliVersion`, `createdAt`, `cwd`, `detail`, `intent`, `name`, `needs`, `nonce`, `pid`, `sessionId`, `short`, `source`, `startedAt`, `state`, `tempo`. Поля `id`, `title`, `label`, `kind`, `status`, `live`, `pinned`, `resumable`, `addressable`, `effect`, `options`, `streamTail`, `jobs` сокет НЕ отдаёт — их добавляет поверх MCP, сшивая ответ демона с собственным состоянием. Пульт выводит `live` и `resumable` сам из факта присутствия записи в `list`, а `pinned` не поддерживает вовсе: пин — состояние чужого инструмента, и тащить его сюда значит завести четвёртый источник правды.

Форм ожидания две, и путать их нельзя — счётчик, который ловит только одну, показывает ноль ровно тогда, когда сессии стоят.

**Первая: сессия сообщает сама.** `state == "blocked"`, при этом `tempo` остаётся `"active"`, а `needs` пустое; причина ожидания ложится в `detail` свободным текстом — например `awaiting user decision on xray-core deb dependency`. Так выглядит сессия, которая сама решила, что дальше без человека не пойдёт.

**Вторая: остановку детектирует демон.** `tempo == "blocked"`, `state` остаётся `"working"`, а `needs` несёт отрендеренный вопрос с вариантами. Так выглядит сессия, упёршаяся в вопрос интерфейса.

Отдельного `state: "waiting"` нет ни в одной из форм.

Но остановка остановке рознь, и валить их в один счётчик нельзя. Пульт различает два состояния простоя:

**Ждёт ответа** — нужен человек и его решение.

**Стоит сама** — человек не нужен, нужно время или действие вне пульта: упёрлась в лимит, требуется вход, ошибка API, ограничение частоты.

Порядок проверки важен, и он не тот, который напрашивается. Сначала читается `needs`, и только если он пуст — флаги:

1. **`needs` непустой** — он и решает. Содержимое из закрытого списка «человек не нужен» — лимит, требуется вход, ошибка API, ограничение частоты — даёт «стоит сама». **Всё остальное, включая незнакомый префикс, даёт «ждёт ответа».**
2. **`needs` пустой, но флаг стоит** — `state == "blocked"` или `tempo == "blocked"` даёт «стоит сама», и строка ОБЯЗАНА нести текст `detail` дословно. В громкий счётчик такая сессия не идёт.

Второе правило выглядит как потеря, но ею не является, и вот почему. Флаги `state` и `tempo` выставляет механизм демона, а не сама сессия: сессия не имеет инструмента, которым пишет их себе, и `detail` при ней составляется тоже не ею — он приходит на другом языке, чем тот, на котором она разговаривает. Значит признак «нужен человек», построенный на флаге, опирается на сигнал, которым никто не управляет, и означает он на деле «что-то происходит», а не «позови человека».

Две сессии, наблюдавшиеся живьём, отличались только словами:

```
state: blocked  tempo: active  needs: ""  detail: "awaiting user decision on xray-core deb dependency"
state: blocked  tempo: active  needs: ""  detail: "awaiting fixes to test coverage & logic"
```

Первой нужен человек, второй — собственные субагенты. Флаги одинаковые, различие целиком в `detail`, и человеку оно очевидно с первого взгляда. Поэтому пульт не пытается угадать: он показывает `detail` и даёт прочесть. Это раздел 2.1 — показывает и передаёт, но не решает.

**Принцип, из которого это следует, шире одного правила.** Демон говорит о происходящем двумя способами: словами — `needs` и `detail` — и флагами — `state` и `tempo`. Слова составляются под конкретное событие и описывают его; флаги выставляются механизмом, чьё поведение мы знаем ровно настолько, насколько успели прочитать в бинаре конкретной версии. Правила пульта строятся на словах. Флаги остаются подсказкой «что-то происходит» и одни, без слов, громкого сигнала не поднимают.

Дисциплина промптов флота — просить сессии писать в `detail` внятную причину — полезна, но несущей конструкцией быть не может: флот открытый, и в него попадут сессии, которых мы не писали.

Почему не наоборот. Флаг `tempo == "blocked"` выставляется в том числе при исчерпании лимита и при отказе биллинга — проверено в коде демона версии 2.1.263, двумя независимыми путями. Если проверять флаг раньше текста, сессия, упёршаяся в лимит, попадёт в счётчик «ждут ответа», и всё разделение обесценится. `needs` — это слова демона о том, что именно происходит, и они точнее флага.

Список «человек не нужен» закрытый намеренно. Правило зависит от словаря префиксов `needs`, а словарь принадлежит демону и будет расти; незнакомое значение обязано попадать в громкий счётчик, а не в тихий. Ошибиться в сторону «позвали зря» дешевле, чем в сторону «промолчали»: первое человек заметит и поправит, второе он не заметит никогда.

Почему это разделение важнее, чем кажется. Изначальное правило «считаем ожидающей по любому из трёх признаков» опиралось на верную мысль, что недооценка опаснее переоценки. Мысль остаётся верной, но у переоценки есть отложенная цена: счётчик «N ждут ответа», мигающий на каждом ограничении частоты, через неделю перестают замечать — и тогда недооценка приходит с другой стороны, через привыкание. Человек, приученный, что счётчик врёт, не посмотрит на него и в тот раз, когда он прав.

Оба состояния видны, и оба заметны — раздел 1 начинается с истории о трёх сессиях, простоявших два часа на уже сброшенном лимите, то есть ровно во втором состоянии. Но это разные сигналы: первый требует действия сейчас, второй сообщает, что работа не идёт. Смешивать их в одно число — значит потерять оба.

Структурных вариантов ответа протокол не даёт: поля `options` не существует. `needs` — одна уже отрендеренная человекочитаемая строка вида `answer: Which colour should the probe use? (Red · Green · Blue)`, где варианты вклеены в хвост через ` · `. Встречаются и другие префиксы: `choose:`, а также аварийные состояния — упёрся в лимит, требуется вход, ошибка API, ограничение частоты.

Отсюда решение по интерфейсу. Хвост `needs` разбирается регуляркой и рисуется кнопками, но это эвристика для подсказки, а не источник правды: отправляется ровно тот текст, который человек видит на кнопке, и рядом всегда есть поле свободного ввода. Если регулярка не сматчилась, показывается только свободный ввод — интерфейс не притворяется, что вариантов не было.

Подписки на изменения сокет не предоставляет, поэтому демон опрашивается с интервалом 2 секунды. Локальный опрос такой частоты стоит пренебрежимо мало.

### 3.2 Лимиты и контекст

**Лимиты аккаунта** приходят с `https://api.anthropic.com/api/oauth/usage`. Нужен OAuth-токен из Keychain macOS: `security find-generic-password -s "Claude Code-credentials" -a "$(whoami)" -w`, поле `.claudeAiOauth.accessToken`. Запрос идёт с заголовком `anthropic-beta: oauth-2025-04-20`. Ответ содержит `five_hour.utilization`, `five_hour.resets_at`, `seven_day.utilization`, `seven_day.resets_at`. Сервер кэширует ответ на 60 секунд — один запрос на все сессии, а не по запросу на каждую.

**Контекст и стоимость сессии** Claude Code передаёт на stdin команде statusline: `.context_window.used_percentage`, `.cost.total_cost_usd`, `.model.display_name`. Со стороны эти данные недоступны, поэтому fleetdeck поставляет собственный statusline-репортёр `fleetdeck-status`: Claude Code запускает его у каждой сессии, он печатает статусную строку и отправляет те же данные в локальный пульт.

Запасной путь, если репортёр не установлен: контекст оценивается по транскрипту как сумма `usage.cache_read_input_tokens`, `usage.cache_creation_input_tokens` и `usage.input_tokens` последнего ответа, делённая на окно модели. Интерфейс помечает такое значение как оценку.

## 4. Интерфейс

Одно окно, три колонки.

**Слева — сессия-оркестратор, всегда открытая.** Это не сессия среди прочих, а постоянное место разговора: переписка и поле ввода. Под перепиской — полоска её собственного контекста.

**По центру — канбан-доска.** Колонки по `stage`: `new`, `active`, `review`, `blocked`, `done`. Цвет левой кромки карточки — `zone` (`urgent`, `unplanned`, `planned`, `niceToHave`). Полоска снизу — `progress`. Клик по карточке открывает панель поверх доски: тело карточки с отрисованными связями, обратные ссылки, поля `stage` и `progress` редактируемыми контролами, ссылка на сессию.

**Справа — список сессий.** У каждой: имя, состояние, сколько молчит, полоска контекста. Ожидающие ответа подняты наверх и выделены.

**Сверху — шапка.** Слева название, справа две шкалы лимитов с процентом и остатком до сброса и два счётчика, которые не прячутся никогда: «N ждут ответа» и «M остановились». Строки во втором всегда несут причину словами — `needs` либо `detail`, — потому что именно по ней человек и понимает, зовут его или нет Первый требует, чтобы человек что-то сделал прямо сейчас; второй сообщает, что работа не идёт по причине, которая рассосётся сама или требует действия вне пульта. Второй счётчик тише первого по оформлению, но так же постоянен.

**Разделы.** Доска и доки — разделы центральной колонки. Доки отрисовывают markdown из настроенного каталога с теми же связями и обратными ссылками, что и карточки. Правка документации в пульте не предусмотрена.

**Панель сессии.** Две вкладки: выжимка (из транскрипта) и живой экран (xterm.js поверх WebSocket). Плюс поле ввода и кнопки: остановить, пнуть, открыть карточку.

## 5. Запись

Пульт умеет ровно два вида записи, больше не умеет ничего.

1. **Ввод в сессию:** текст и выбор варианта в ожидающем вопросе. Выбор варианта — это тот же текст: отправляется ровно то, что человек прочитал на кнопке.
2. **Правка полей карточки:** `stage` и `progress`. Тело карточки пульт не трогает — его пишут агенты.

Ввод в сессию идёт операцией `reply` и требует control key из `~/.claude/daemon/control.key` (раздел 3.1). Ключ читается при старте, в память, и дальше обращается как секрет: не логируется, не попадает в снимок состояния, не уходит в ответы API и не появляется в тексте ошибок — то же правило, что у OAuth-токена в разделе 3.2. Ошибка формулируется как «control key unavailable», без содержимого и без пути с домашним каталогом в пользовательском тексте.

Если ключа нет, он пуст или не читается, запись в сессии выключается целиком, а причина видна в интерфейсе. Молча превратиться в режим только для чтения нельзя: человек должен понимать, почему поле ввода не работает, иначе он будет считать сломанным пульт, а не отсутствующий ключ.

Запись в карточку хирургическая: файл перечитывается непосредственно перед записью, меняется только нужное поле, остальное сохраняется байт в байт. Это то же правило, по которому живёт скил `card-keeping`, и оно защищает от гонки с агентом, пишущим в ту же карточку свой лог.

После записи пульт коммитит изменение в git с внятным сообщением. Иначе доска расползается между рабочим деревом и историей.

**Гонка записи существует, и она принята осознанно.** Пульт правит два поля фронтматтера, агент в то же время дописывает строку в лог той же карточки. Пульт перечитывает файл непосредственно перед записью и пишет атомарно — во временный файл рядом и `rename` поверх, — поэтому читатель никогда не увидит полуфайл. Но окно между чтением и переименованием отличается от нуля, и дописка, сделанная агентом внутри этого окна, теряется. Измерено под искусственным давлением: одна потеря на двести итераций.

Замок здесь не ставится намеренно. Агенты дописывают в карточку обычным редактированием файла и никакого `flock` не возьмут, так что замок со стороны пульта закрыл бы ноль, а в коде читался бы как защита — то есть стал бы утверждением, под которым ничего нет. Закрыть гонку по-настоящему можно только изменением конвенции: либо агенты пишут в карточку исключительно через пульт, либо обе стороны честно берут один замок. Оба варианта меняют способ работы флота, а не устройство пульта, и потому остаются решением на будущее.

Цена принятого решения названа честно: в редком случае теряется строка агентского лога. Доска остаётся обычными markdown-файлами, которые правит кто угодно чем угодно, — и это её главное свойство, ради которого гонка и терпится.

## 6. Уведомления

Решение о том, когда дёрнуть человека, принимает сервер, а не браузер: сервер и так знает всё состояние, а баннер через `osascript` не зависит от того, открыта ли вкладка.

Правила первой версии:

- сессия ждёт ответа;
- сессия завершилась с ошибкой;
- сессия молчит дольше настроенного порога;
- карточка ушла в `blocked` или `review`.

Каждое правило выключается в настройках. Повторные баннеры по одному и тому же событию не шлются: событием считается смена состояния, а не его наличие.

**Молчание измеряется по транскрипту**: сколько времени прошло с последней записи в файл сессии. Транскрипта может не быть вовсе — сессия только что стартовала, файл ещё не создан, сессия чужого бэкенда. Это состояние — «не измерено», а не «молчит бесконечно», и правило по такой сессии не срабатывает: иначе баннер «молчит дольше получаса» получала бы каждая только что запущенная сессия, у которой транскрипт появится через секунду. Транскрипт растёт только когда сессия что-то делает, поэтому его возраст и есть длительность молчания. Правило применяется ко всем сессиям без исключения — в том числе к остановившимся: сессия, упёршаяся в лимит, именно молчит, и раздел 1 закрывается этим правилом, а не отдельным правилом про лимиты. Исключение одно: сессия, которую человек сам останавливает, не даёт баннеров ни по одному правилу.

**Ключ подавления повтора отпускается, когда сессия исчезает из списка демона.** Иначе короткий идентификатор, доставшийся новой сессии, унаследует чужую отметку «уже сообщали», и первый же настоящий вопрос этой сессии пройдёт молча.

## 7. Отказы

Пульт деградирует по частям и не падает целиком.

| Что отказало | Поведение |
| --- | --- |
| Демон не поднят, сокета нет | «Демон недоступен»; доска и доки работают |
| Ручка `usage` недоступна или токен протух | Шкалы гаснут с пояснением; остальное работает |
| Репортёр не установлен | Контекст из транскрипта, помечен как оценка |
| Битый frontmatter в карточке | Карточка помечена «не разбирается»; доска цела |
| Карточку правят пульт и агент одновременно | Перечитать перед записью, писать только своё поле |
| Конфликт в git при записи | Не перезаписывать, показать и дать решить человеку |
| Карточка ссылается на мёртвую сессию | Показать «сессия мертва», предложить отвязать |
| Транскрипт в десятки мегабайт | Читать хвостом, целиком не грузить |

Отдельно: ручка `oauth/usage` неофициальная, работает по бета-заголовку и может измениться без предупреждения. Её отказ обязан гасить шкалы, а не ронять пульт.

## 8. Безопасность

Пульт читает OAuth-токен из Keychain macOS и отправляет его **только** на `api.anthropic.com`. Токен не логируется, не пишется на диск и не передаётся в браузер. Это должно быть сказано прямым текстом в README: инструмент, который трогает чужие учётные данные, обязан объяснить, что именно он с ними делает.

Сервер слушает только `127.0.0.1`. Ввод в сессии — действие с последствиями, поэтому пульт передаёт то, что напечатал человек, и ничего не додумывает.

## 9. Тесты

Ведущий принцип, выведенный из разбора реальных дефектов в предыдущих задачах:

> Проверка обязана отличать «посмотрел и не нашёл» от «смотреть было не на что», и второе — это отказ, а не успех.

Практически:

- на пустом каталоге карточек, отсутствующем сокете, битом JSON и протухшем токене каждая проверка обязана давать внятный отказ, а не тихий зелёный;
- фикстуры — настоящие хвосты `jsonl` и настоящие ответы сокета, обезличенные;
- ядро разбора протокола, выжимки и frontmatter покрывается мутационной проверкой: тест, переживающий порчу кода, ничего не проверяет;
- хирургическая запись поля проверяется на карточке, изменённой между чтением и записью.

## 10. Устройство репозитория

```text
fleetdeck/
  cmd/fleetdeck/          сервер
  cmd/fleetdeck-status/   statusline-репортёр
  internal/daemon/        клиент control.sock
  internal/transcript/    выжимка из jsonl
  internal/board/         карточки: чтение, хирургическая запись, git
  internal/usage/         лимиты и кэш
  internal/notify/        баннеры через osascript
  internal/server/        HTTP и WebSocket
  web/                    фронтенд, вшивается через embed
  plugin/                 плагин Claude Code: скилы, шаблон доски, валидатор
  README.md               английский
  README.ru.md            русский
  docs/en/                документация для людей, английская
  docs/ru/                документация для людей, русская
  docs/superpowers/specs/ дизайн-документы, русские
```

Каждый пакет в `internal/` отвечает за один источник или одну заботу и не знает о вебе. Сервер собирает их вместе и остаётся тонким.

### 10.1 Язык документации

Документация для людей ведётся на двух языках: английский — основной, русский — равноправная копия. `README.md` английский и ссылается на `README.ru.md` первой строкой, русский ссылается на английский.

Дизайн-документы в `docs/superpowers/specs/` остаются русскими: это внутренние рабочие документы, а не то, что читает пользователь.

Правило поддержки: изменение, которое трогает поведение и требует правки документации, правит обе версии в одном коммите. Разъехавшийся перевод хуже отсутствующего — он врёт с видом достоверности.

Комментарии в коде, сообщения об ошибках в интерфейсе и текст коммитов — английские.

## 11. Настройки

Конфигурация лежит в `~/.config/fleetdeck/config.yaml` и создаётся командой `fleetdeck init` со значениями по умолчанию. Пульт работает и без файла: отсутствующий файл — это набор умолчаний, а не отказ.

| Ключ | Умолчание | Смысл |
| --- | --- | --- |
| `board.path` | пусто | Каталог доски. Пусто — доска не показывается, пульт работает как управление сессиями |
| `docs.paths` | пусто | Каталоги с документацией для раздела «Доки» |
| `orchestrator.session` | пусто | Короткий id сессии, закреплённой в левой колонке. Пусто — колонка предлагает выбрать |
| `notify.enabled` | все правила | Какие из четырёх правил уведомлений включены |
| `notify.silence_after` | 30 минут | Сколько сессия должна молчать, чтобы это считалось событием. Ноль выключает правило молчания целиком |
| `daemon.poll_interval` | 2 секунды | Частота опроса демона |
| `usage.enabled` | да | Опрашивать ли ручку лимитов. Выключено — шкалы не показываются вовсе |
| `server.port` | 7777 | Порт на `127.0.0.1` |

Настройки, которые человек меняет из интерфейса — переключатели уведомлений и закреплённая сессия оркестратора, — пульт записывает обратно в тот же файл.

## 12. Установка

1. Бинарь из GitHub Releases либо `go install`.
2. `fleetdeck init` — создаёт конфигурацию, ставит launchd-агент, прописывает `fleetdeck-status` в `settings.json`, создаёт доску из шаблона, если её нет.
3. Плагин Claude Code ставится через marketplace.

## 13. Порядок реализации

Работа разбита на два плана, потому что один вышел бы неподъёмным, а граница между ними проходит по естественному шву.

**План первый — сервер и данные.** Клиент протокола демона, выжимка из транскриптов, чтение и хирургическая запись карточек с git, лимиты, statusline-репортёр, уведомления, HTTP и WebSocket с полным API. Итог: рабочий сервер, у которого всё проверяемо тестами и curl, без единой строки интерфейса.

**План второй — интерфейс и поставка.** Фронтенд: три колонки, канбан, панель карточки, выжимка и живой терминал. Плюс `fleetdeck init`, launchd-агент, сборка релизов, переезд плагина и документация на двух языках.

Такой шов даёт проверяемый промежуточный результат: после первого плана сервер можно гонять руками и убедиться, что данные верные, до того как в дело вступит вёрстка. Обратный порядок дал бы красивую картинку поверх непроверенных данных.

## 14. Переезд конвенции

Плагин `agent-fleet` уезжает из приватного репозитория целиком и там удаляется: две копии конвенции разъедутся, и это вопрос времени.

Обезличить при переезде три места: автора в `.claude-plugin/plugin.json`, имя мейнтейнера в README шаблона доски, имя рабочего репозитория в тестовой фикстуре валидатора. Сами значения не называются: репозиторий публичный, и перечень того, что мы прячем, прятать надо тоже.

Из шаблона доски удаляется `Доска.base` — файл видов Obsidian. Виды теперь даёт пульт.
