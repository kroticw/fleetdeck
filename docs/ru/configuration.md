# Конфигурация

fleetdeck настраивается одним YAML-файлом. Эта страница перечисляет каждый ключ, который он распознаёт, значение по умолчанию для каждого и что именно происходит, если значение неверно.

## Ключи конфигурации

| Путь YAML | Тип | По умолчанию | Что ломается при неверном значении |
| --- | --- | --- | --- |
| `board.path` | строка | не задано (пусто) | не проверяется |
| `docs.paths` | список строк | не задано (пусто) | не проверяется |
| `orchestrator.session` | строка | не задано (пусто) | не проверяется |
| `notify.enabled.waiting` | булево | `true` | не проверяется (должно быть булевым) |
| `notify.enabled.failed` | булево | `true` | не проверяется (должно быть булевым) |
| `notify.enabled.silent` | булево | `true` | не проверяется (должно быть булевым) |
| `notify.enabled.card_blocked` | булево | `true` | не проверяется (должно быть булевым) |
| `notify.silence_after` | длительность | `30m` | отрицательное значение: `notify.silence_after must not be negative, got %s`. Голое число: `must be a duration string like "30s", not a bare number (%s)`. Не-скалярное значение (например, список): `line %d: must be a duration string like "30s"`. Некорректный текст длительности: `line %d:`, за которым следует собственная ошибка разбора Go, например `time: invalid duration "abc"` |
| `daemon.poll_interval` | длительность | `2s` | ноль или отрицательное значение: `daemon.poll_interval must be positive, got %s`. Голое число, не-скалярное значение или некорректный текст: те же три формы, что и у `notify.silence_after` выше |
| `usage.enabled` | булево | `true` | не проверяется (должно быть булевым) |
| `server.port` | целое число | `7777` | вне диапазона от 1 до 65535: `server.port must be between 1 and 65535, got %d` |

Включение одного из ключей `notify.enabled.*` включает правило, но не гарантирует, что баннер будет увиден, — почему, смотрите в разделе [«Ограничения»](../../README.ru.md#ограничения) README.

`board.path` называет корневой каталог доски, а не каталог, где карточки лежат напрямую: пульт читает карточки из подкаталога `cards` внутри него (`<board.path>/cards/*.md`) — так же, как устроен `plugin/templates/board/` (`cards/`, `archive/`, `scripts/`, `README.md`). Если `board.path` существует, но в нём нет подкаталога `cards`, это отдельная, более точная ошибка, чем пустая доска.

`docs.paths` перечисляет каталоги, из которых читает раздел документации. В список попадает каждый markdown-файл внутри них, а сам документ отдаётся только тогда, когда путь к нему разрешается внутрь одного из этих каталогов: симлинк, лежащий в каталоге документации и указывающий наружу, отклоняется — ровно так же, как отклоняется правка карточки за пределами каталога доски. Ничего, кроме markdown, не отдаётся, поэтому из каталога, где заметки лежат рядом с учётными данными, наружу уйдут только заметки. Ненастроенные каталоги и настроенные, но нечитаемые, называются прямо, а не показываются как пустой набор документации: «документации нет» и «каталога, который вы указали, не существует» — разные утверждения, и правкой этого файла лечится только второе.

## Пример файла

```yaml
board:
  path: /path/to/board
docs:
  paths:
    - /path/to/docs
orchestrator:
  session: some-session-id
notify:
  enabled:
    waiting: true
    failed: true
    silent: true
    card_blocked: true
  silence_after: 30m
daemon:
  poll_interval: 2s
usage:
  enabled: true
server:
  port: 7777
```

## Отсутствующие, пустые и повреждённые файлы

Файл конфигурации, который не существует, не является ошибкой: загрузка откатывается ко всем значениям по умолчанию из таблицы выше. Файл, который существует, но разбирается вообще ни во что — потому что он пуст или содержит только комментарии, — обрабатывается точно так же, как набор значений по умолчанию. Файл с по-настоящему сломанным синтаксисом YAML — это жёсткая ошибка, и загрузка завершается неудачей.

## Неизвестные ключи

Нераспознанный ключ отклоняется, а не игнорируется. Сюда входит и ключ, который выглядит похожим, но не совпадает в точности, — например, плоский `board_path` вместо вложенной формы `board: {path: ...}`. Ошибка называет проблемный ключ напрямую, например `unknown configuration key "pathx"`, а не показывает сырую ошибку типа из библиотеки YAML.

## Более одного YAML-документа

Файл, содержащий более одного YAML-документа (разделённых строкой `---` посреди файла), отклоняется с сообщением `parse config %s: file contains more than one YAML document`.

## Запись длительностей

`notify.silence_after` и `daemon.poll_interval` должны быть записаны как строка YAML, содержащая длительность Go, например `"30s"`, `"2s"` или `"45m"`. Запись голого числа вместо этого — например, `poll_interval: 2` — отклоняется с ошибкой, которая называет и то, что ожидалось («строка длительности»), и то, что найдено («голое число»), а не выдаёт общее сообщение о несовпадении типов. Запись не-скалярного значения, такого как список YAML, также отклоняется, и ошибка называет строку, где это произошло.

## Что означает `silence_after: 0` и что делает отрицательное значение

`notify.silence_after` — это длительность времени, которое сессия должна молчать, прежде чем это молчание засчитывается как событие, достойное уведомления. Ни одна сессия не может молчать меньше нуля времени, поэтому порог, буквально прочитанный как ноль, срабатывал бы на каждой сессии немедленно. По этой причине `silence_after: 0` определено как полное отключение правила молчания, а не как «уведомлять мгновенно». Отрицательное значение, напротив, отклоняется прямо как ошибка, а не получает какое-либо особое значение.

## Где живёт файл конфигурации

Сегодня для файла конфигурации нет пути поиска по умолчанию или неявного пути. Коду, который загружает конфигурацию, путь к файлу должен передаваться явно; ничто в этом репозитории пока его не вызывает, и нет ни флага командной строки, ни переменной окружения, которые бы его предоставляли.

Задуманное расположение, как только появятся бинарь `fleetdeck` и команда `init`, которая его запишет, — `~/.config/fleetdeck/config.yaml`. Этот путь — часть замысла, а не то, что этот код читает или пишет сегодня.
