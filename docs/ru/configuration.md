# Конфигурация

fleetdeck настраивается одним YAML-файлом. Эта страница перечисляет каждый ключ, который он распознаёт, значение по умолчанию для каждого и что именно происходит, если значение неверно.

## Ключи конфигурации

<!-- fleetdeck:config-keys: эту таблицу сверяет с internal/config тест TestConfigurationPageListsEveryKey. У ключа, объявленного там, здесь обязана быть строка — на обоих языках и со всеми четырьмя заполненными колонками. -->

| Путь YAML | Тип | По умолчанию | Что ломается при неверном значении |
| --- | --- | --- | --- |
| `board.path` | строка | не задано (пусто) | не проверяется |
| `docs.paths` | список строк | не задано (пусто) | не проверяется |
| `orchestrator.session` | строка | не задано (пусто) | не проверяется |
| `session_labels` | отображение UUID сессии в строку | не задано (пусто) | не проверяется; ключ, не являющийся UUID сессии, сохраняется и ни с чем не совпадает |
| `notify.enabled.waiting` | булево | `true` | не проверяется (должно быть булевым) |
| `notify.enabled.failed` | булево | `true` | не проверяется (должно быть булевым) |
| `notify.enabled.silent` | булево | `true` | не проверяется (должно быть булевым) |
| `notify.enabled.card_blocked` | булево | `true` | не проверяется (должно быть булевым) |
| `notify.silence_after` | длительность | `30m` | отрицательное значение: `notify.silence_after must not be negative, got %s`. Голое число: `must be a duration string like "30s", not a bare number (%s)`. Не-скалярное значение (например, список): `line %d: must be a duration string like "30s"`. Некорректный текст длительности: `line %d:`, за которым следует собственная ошибка разбора Go, например `time: invalid duration "abc"` |
| `daemon.poll_interval` | длительность | `2s` | ноль или отрицательное значение: `daemon.poll_interval must be positive, got %s`. Голое число, не-скалярное значение или некорректный текст: те же три формы, что и у `notify.silence_after` выше |
| `usage.enabled` | булево | `true` | не проверяется (должно быть булевым) |
| `server.port` | целое число | `7777` | вне диапазона от 1 до 65535: `server.port must be between 1 and 65535, got %d` |
| `statusline.wrap` | строка (команда оболочки) | не задано (без обёртки) | до запуска не проверяется; команда, которую не удалось запустить или которая вышла с ненулевым кодом, считается отсутствием обёртки, и `fleetdeck-status` печатает свою строку |
| `statusline.rate_limits_path` | строка (путь к файлу) | не задано (ничего не пишется) | не проверяется; путь, в который не удалось записать, нигде не сообщается, и панель берёт лимиты аккаунта из сети |
| `name` | строка | папка над `board.path`, `main`, если она ничего не говорит | пустое имя, пробелы вокруг или управляющий символ: `the top-level fleet: name ...`; имя другого флота: см. [Несколько флотов](#несколько-флотов) |
| `fleets` | список флотов | не задан (пусто) | см. [Несколько флотов](#несколько-флотов) |
| `fleets[].name` | строка | нет: обязателен | пусто, пробелы по краям или управляющий символ: `fleets[N]: name ...`; имя другого флота: `fleets[1]: name "clining" is already the name of fleets[0]` |
| `fleets[].board.path` | строка | нет: обязателен | не задан: `fleets[N]: board path must be set`; доска другого флота: `fleets[1]: board "..." is already the board of the top-level fleet ("main")` |
| `fleets[].docs.paths` | список строк | не задано (пусто) | не проверяется, как и `docs.paths` |
| `fleets[].orchestrator.session` | строка | не задано (пусто) | оркестратор другого флота: `fleets[1]: orchestrator "06a1f607" is already the orchestrator of the top-level fleet ("main")` |

`fleets[]` означает любую запись списка `fleets`: записи устроены одинаково, поэтому их ключи описаны один раз, а не для каждого флота отдельно.

Включение одного из ключей `notify.enabled.*` включает правило, но не гарантирует, что баннер будет увиден, — почему, смотрите в разделе [«Ограничения»](../../README.ru.md#ограничения) README.

`board.path` называет корневой каталог доски, а не каталог, где карточки лежат напрямую: пульт читает карточки из подкаталога `cards` внутри него (`<board.path>/cards/*.md`) — так же, как устроен `plugin/templates/board/` (`cards/`, `archive/`, `scripts/`, `README.md`). Если `board.path` существует, но в нём нет подкаталога `cards`, это сообщается как указание не на тот каталог. Пустой подкаталог `cards` — это пустая доска, а не ошибка: новая доска начинается именно так.

`docs.paths` перечисляет каталоги, из которых читает раздел документации. В список попадает каждый markdown-файл внутри них, а сам документ отдаётся только тогда, когда путь к нему разрешается внутрь одного из этих каталогов: симлинк, лежащий в каталоге документации и указывающий наружу, отклоняется — ровно так же, как отклоняется правка карточки за пределами каталога доски. Ничего, кроме markdown, не отдаётся, поэтому из каталога, где заметки лежат рядом с учётными данными, наружу уйдут только заметки. Ненастроенные каталоги и настроенные, но нечитаемые, называются прямо, а не показываются как пустой набор документации: «документации нет» и «каталога, который вы указали, не существует» — разные утверждения, и правкой этого файла лечится только второе.

`session_labels` — это собственное имя, которое оператор дал сессии; ключ здесь — UUID транскрипта сессии, а не её короткий идентификатор: короткий идентификатор демон может позже отдать другой сессии, и подпись, переживающая такую передачу, — вся причина ключевать именно по UUID. Записи пишет пульт: переименование сессии в колонке оркестратора добавляет, меняет или удаляет ровно одну из них, а пустое имя удаляет запись, а не сохраняет пустую, — иначе конфигурация, которая только набирает записи, со временем забилась бы подписями сессий, которых никто не помнит. Сессии, у которой демон и так сообщает имя, запись здесь не нужна; она нужна тем, что запустились без имени и переименованию после факта не поддаются.

`statusline.wrap` и `statusline.rate_limits_path` читает `fleetdeck-status` — репортёр статусной строки, которого Claude Code запускает у каждой сессии, — и читает только тогда, когда не заданы его собственные флаги `-wrap` и `-rate-limits-path`. `wrap` называет вашу собственную команду статусной строки: `fleetdeck-status` прогоняет через неё свой stdin и печатает полученное без изменений, поэтому привычная статусная строка продолжает работать, а пульт стоит за ней. `rate_limits_path` — файл, в который пишутся окна лимитов, пришедшие в том же stdin; этот файл для панели первый источник лимитов аккаунта, вперёд сети. По умолчанию не задано ни то, ни другое, и «не задано» означает «выключено»: без обёртки и без записи. Запасного пути у `rate_limits_path` сознательно нет — неявный путь, которого запуск руками коснулся, не имея этого в виду, стоил двух инцидентов за один вечер.

## Несколько флотов

Один пульт может вести несколько флотов — у каждого своя доска, своя документация и свой оркестратор, — а вкладка браузера показывает один из них, как IDE показывает один проект.

Верхние ключи `board`, `docs` и `orchestrator` — первый флот, ровно как в конфигурации, написанной до появления флотов, а `name` даёт ему имя. Каждый следующий флот — запись списка `fleets` с теми же ключами, перечисленными в таблице выше как `fleets[].*`; `board.path` у неё обязателен:

```yaml
board:
  path: /Users/me/fleetdeck/board
docs:
  paths:
    - /Users/me/fleetdeck/docs
orchestrator:
  session: 06a1f607
name: main
fleets:
  - name: clining
    board:
      path: /Users/me/clining-fleet/board
    docs:
      paths:
        - /Users/me/clining-fleet/docs
    orchestrator:
      session: 1a2b3c4d
```

Конфигурация, в которой пульт не смог бы различить флоты, отвергается, и ошибка называет, где в файле ошибка — `the top-level fleet` или `fleets[N]`:

- два флота с одним именем: `fleets[1]: name "clining" is already the name of fleets[0]`;
- одна сессия оркестратором двух флотов: она читала бы две доски;
- два флота на одной доске: они претендовали бы на одни и те же сессии;
- запись `fleets` без `board.path`.

Что у флотов общее: один пульт на `server.port`, сами сессии Claude Code, лимиты аккаунта, правила уведомлений, подписи сессий и статусная строка. Пульт один, а не по одному на флот, потому что статусная строка каждой сессии шлёт данные на `127.0.0.1:7777` и больше никуда: пульт на другом порту не услышал бы ни одной сессии.

Какие сессии принадлежат флоту, нигде не хранится: сессия во флоте, если она его оркестратор или если её называет поле `session` карточки на доске этого флота. Вкладка показывает сессии своего флота, затем сессии, на которые не претендует ни один флот, — они видны в каждом флоте, чтобы вопрос не остался там, куда не смотрит ни одна вкладка, — и каждый другой флот одной строкой с числом его сессий, ждущих ответа. Переключатель в шапке несёт то же число для каждого флота, а баннер называет флот, из которого пришёл.

Флот вкладки записан в её адресе, `?fleet=ИМЯ`; без параметра — первый флот. Переход на другой флот перезагружает страницу: терминалы ушедшего флота закрываются, его сессиям ничего не отправляется.

Флот добавляет `fleetdeck init --fleet ИМЯ --workspace ПАПКА` — см. [Начало работы](getting-started.md#второй-флот). Работающий пульт покажет его после перезапуска.

fleetdeck из версии до появления этого ключа отвергает конфигурацию с `name` или `fleets` ошибкой `unknown configuration key "fleets"`: обновите приложение, прежде чем добавлять второй флот, и не возвращайтесь на старую версию, пока он в конфигурации есть.

## Пример файла

```yaml
board:
  path: /path/to/board
docs:
  paths:
    - /path/to/docs
orchestrator:
  session: some-session-id
notify:
  enabled:
    waiting: true
    failed: true
    silent: true
    card_blocked: true
  silence_after: 30m
daemon:
  poll_interval: 2s
usage:
  enabled: true
server:
  port: 7777
```

## Отсутствующие, пустые и повреждённые файлы

Файл конфигурации, который не существует, не является ошибкой: загрузка откатывается ко всем значениям по умолчанию из таблицы выше. Файл, который существует, но разбирается вообще ни во что — потому что он пуст или содержит только комментарии, — обрабатывается точно так же, как набор значений по умолчанию. Файл с по-настоящему сломанным синтаксисом YAML — это жёсткая ошибка, и загрузка завершается неудачей.

## Неизвестные ключи

Нераспознанный ключ отклоняется, а не игнорируется. Сюда входит и ключ, который выглядит похожим, но не совпадает в точности, — например, плоский `board_path` вместо вложенной формы `board: {path: ...}`. Ошибка называет проблемный ключ напрямую, например `unknown configuration key "pathx"`, а не показывает сырую ошибку типа из библиотеки YAML.

## Более одного YAML-документа

Файл, содержащий более одного YAML-документа (разделённых строкой `---` посреди файла), отклоняется с сообщением `parse config %s: file contains more than one YAML document`.

## Запись длительностей

`notify.silence_after` и `daemon.poll_interval` должны быть записаны как строка YAML, содержащая длительность Go, например `"30s"`, `"2s"` или `"45m"`. Запись голого числа вместо этого — например, `poll_interval: 2` — отклоняется с ошибкой, которая называет и то, что ожидалось («строка длительности»), и то, что найдено («голое число»), а не выдаёт общее сообщение о несовпадении типов. Запись не-скалярного значения, такого как список YAML, также отклоняется, и ошибка называет строку, где это произошло.

## Что означает `silence_after: 0` и что делает отрицательное значение

`notify.silence_after` — это длительность времени, которое сессия должна молчать, прежде чем это молчание засчитывается как событие, достойное уведомления. Ни одна сессия не может молчать меньше нуля времени, поэтому порог, буквально прочитанный как ноль, срабатывал бы на каждой сессии немедленно. По этой причине `silence_after: 0` определено как полное отключение правила молчания, а не как «уведомлять мгновенно». Отрицательное значение, напротив, отклоняется прямо как ошибка, а не получает какое-либо особое значение.

## Где живёт файл конфигурации

`fleetdeck` читает конфигурацию из пути, который называет флаг `--config`. Значение по умолчанию, когда флаг не задан, — `~/.config/fleetdeck/config.yaml` (`defaultConfigPath` в `cmd/fleetdeck/main.go`). `fleetdeck init` записывает этот путь по умолчанию при первом запуске, если там ещё ничего нет. Пульт, который не находит файла по своему пути, вместо доски показывает страницу настройки и записывает файл туда, когда выбрана рабочая папка, — см. [`getting-started.md`](getting-started.md#первый-запуск-выбор-рабочей-папки). Файл, который существует, но не разбирается, — это ошибка, а не повод предлагать настройку.

## Изолированный стенд

Панель, поднятая для проверки или приёмки рядом с реально работающим флотом, всё равно находит настоящего демона: сокет ищется по uid текущего пользователя под `/tmp`, а не по тому, что называет `--config`, так что отдельный файл конфигурации, отдельный `HOME` и отдельная доска её не изолируют. Колонка сессий такого стенда уже показывала настоящие сессии флота и отрывки сообщений, а открытие одной из них на стенде меняет размер настоящего терминала этой сессии для всех, кто к ней подключён, включая оператора — по умолчанию стенд здесь не зритель, а вторая незваная рука на тех же живых сессиях.

`--stand-socket` закрывает это: получив путь, панель подключается только к нему и вообще не выполняет обнаружение настоящего демона — у двух путей в коде нет ничего общего, так что настоящему демону негде найтись в качестве отката. Заданный, но пустой (незаполненная переменная скрипта, попавшая в `--stand-socket=`) отклоняется при запуске, а не читается как «не задан». Скопируйте весь блок целиком, чтобы поднять стенд, который не сможет достать демона живого флота, что бы ещё ни работало на машине:

```bash
tmp=$(mktemp -d) && cat > "$tmp/config.yaml" <<'YAML'
server:
  port: 7799
YAML
fleetdeck -config "$tmp/config.yaml" -stand-socket "$tmp/no-daemon-here.sock"
```

Колонка сессий на так запущенном стенде читается пустой или показывает ошибку демона — никогда чужие данные, — потому что по этому пути никто не слушает, а больше никуда это устройство и не посмотрит.

У стенда самого первого запуска файла конфигурации нет, значит, нет и `server.port`, который увёл бы его с порта оператора: порт даёт `--port`. Ещё ему нужен собственный домашний каталог, потому что настройка пишет конфигурацию, `settings.json` Claude Code и историю git доски в домашний каталог:

```bash
tmp=$(mktemp -d) && HOME="$tmp/home" fleetdeck -port 7799 -stand-socket "$tmp/no-daemon-here.sock"
```

Откройте `http://127.0.0.1:7799/` — страница настройки предложит `$tmp/home/fleetdeck`. Всё, что пишет настройка, оказывается внутри `$tmp/home`.

Мастер оркестратора умеет запускать сессию, и сокет этому не мешает: он запускает её через `claude --bg`, а настоящий claude достаёт настоящего демона, какой бы сокет ни читал пульт. Поэтому стенд запускает сессии только тем claude, который ему дали в `--stand-claude`, а без него не запускает ни одной — кнопка новой сессии в мастере выключена и говорит почему. Искать claude на стенде пульт не станет никогда, так же как не ищет там демона. `--stand-claude` без `--stand-socket` или пустой отклоняется при запуске. Claude для стенда — что угодно, что печатает то же, что `claude --bg`, — строку `backgrounded · <short id> · <имя>`, — и добивается, чтобы демон стенда показал эту сессию.

Цена такой изоляции, чтобы её не находили только натолкнувшись: клиент, привязанный через `--stand-socket`, не замечает, если демон за ним перезапустится под новым сокетом, в отличие от обычного обнаружения (собственный `daemonClient` в `cmd/fleetdeck/main.go`). Разовому стенду для приёмки это безразлично; долгоживущий тестовый флот на этом флаге потребовал бы перезапуска вместе со своим демоном.

## Где живут остальные файлы

Лог пульта — `~/Library/Logs/fleetdeck.log`: приложение fleetdeck дописывает туда оба потока вывода пульта, который запускает. Как приложение запускает и держит пульт — в [`getting-started.md`](getting-started.md#приложение-и-пульт).
