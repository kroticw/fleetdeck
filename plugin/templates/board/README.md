# Доска флота агентов

Источник правды по смыслу задач, которые выполняют фоновые сессии Claude Code.

## Что здесь есть

- `cards/` — по одному файлу на задачу, имя `T-NNN-YYYY-MM-DD-slug.md`.
- `archive/AGENTS-ARCHIVE.md` — реестр снесённых сессий.
- `.ids/` — реестр захваченных номеров карточек, пустые файлы.
- `scripts/new_card.py` — заведение карточки с выдачей номера.
- `scripts/card_path.py` — путь карточки по её номеру.
- `scripts/validate_cards.py` — проверка схемы карточек.
- `scripts/backfill_ids.py` — раздача номеров карточкам, заведённым раньше.

Видов доска не хранит: срезы «в работе», «на ревью» и «всё» рисует пульт
fleetdeck, читая эти же карточки.

Регламент работы с доской лежит не здесь, а в плагине `agent-fleet`:
скил `fleet-orchestrator` — для того, кто раздаёт задачи, скил
`card-keeping` — для агента, который ведёт свою карточку.

## Чего здесь нет намеренно

Состояния сессии: жива ли она, чем занята, запинена ли. Это знает демон
Claude Code, и дублировать его сюда нельзя — иначе появится второй источник
правды, который начнёт врать. Живое состояние смотрят через `list_sessions`
или FleetView.

## Схема карточки

| Поле | Значения | Обязательное |
| --- | --- | --- |
| `id` | `T-NNN`, сквозной номер по всей доске | да |
| `zone` | `urgent`, `unplanned`, `planned`, `niceToHave` | да |
| `stage` | `new`, `active`, `review`, `done`, `blocked` | да |
| `progress` | `0`, `10`, `20`, `40`, `60`, `80`, `100` | да |
| `session` | short id фоновой сессии | при `stage: new` нет, дальше да |
| `repo` | путь репозитория относительно домашнего каталога | нет |
| `created` | `YYYY-MM-DD` | да |

Других полей во frontmatter быть не должно: валидатор отвергает незнакомое
поле. Так принцип «одно поле — один источник правды» держится не только на
прозе в скилах.

Конвенция прогресса: `0` заведена · `10` запущен · `20` работает ·
`40` черновик отдан · `60` итерация · `80` почти · `100` готово вместе с
`stage: done`.

## Идентификатор карточки

Чтобы на задачу можно было указать словом, у карточки есть короткий номер: `T-013`. Он сквозной по всей доске, а не по проекту: репозиторий у задачи меняется — задачу переносят, проект переименовывают, — а номер обязан остаться тем же.

Номер живёт в двух местах: в поле `id` и в начале имени файла. Имя даёт поиск по номеру в Obsidian и колонку в видах доски; поле даёт свойство, читаемое машиной и Bases. Разойтись им не даёт валидатор.

Идентификатор говорит только о карточке. Связь карточки с сессией — это по-прежнему поле `session`, и оно единственное.

Найти карточку по номеру:

```bash
python3 scripts/card_path.py T-13
```

Скрипт нормализует номер и печатает путь. Ищет он по полю `id`, а не по имени файла, поэтому находит и карточку, которую ещё не переименовали. Номер всегда трёхзначный — сказанное вслух «T-13» это `T-013`.

**Сессия, которая ведёт карточку, адресует её номером, а не путём.** Имя файла может измениться под работающей сессией: так уже терялась запись — карточку переименовали, пока сессия писала в неё лог. Поэтому путь берётся резолвом непосредственно перед обращением к файлу, а «файл не найден» читается как переезд, а не как повод создать карточку заново.

## Как завести карточку

Только скриптом:

```bash
python3 scripts/new_card.py \
  --title "Заголовок карточки" \
  --slug short-slug \
  --zone planned \
  --repo example/project
```

Руками карточки не заводят. Скрипт захватывает номер в реестре `.ids/`: создание файла-маркера через `O_EXCL` — единственная операция, которую файловая система выдаёт строго однажды. Карточки заводятся параллельно оператором, оркестратором и самими сессиями, и «взять максимум и прибавить единицу» при двух одновременных заведениях выдаёт один номер двум карточкам.

Маркер не удаляется никогда: ни при переименовании карточки, ни когда она уезжает в архив. Номер нельзя освободить и нельзя переиспользовать.

**Каталог `.ids/` обязан быть в git.** Он скрытый и состоит из пустых файлов, поэтому дописать его в `.gitignore` кажется безобидным — но он и есть источник занятых номеров. Без него свежий клон начнёт раздавать номера заново поверх существующих карточек.

Валидатор проверяет, что у каждой карточки номер захвачен, — так правило «только скриптом» держится проверкой, а не просьбой.

Карточкам, заведённым до появления номеров, номера раздаёт `scripts/backfill_ids.py`: он проставляет `id`, переименовывает файлы и чинит ссылки на них, пропуская карточки живых сессий.

## Кто что пишет

До спавна карточку ведёт оркестратор: заводит её в `stage: new`,
`progress: 0`, заполняет `zone`, `created`, `repo`, заголовок и «Контекст»,
поднимает сессию и вписывает её short id в `session` — и только после этого
отправляет агенту задачу. К моменту, когда агент начинает работать, поле
`session` уже на месте.

После спавна карточку ведёт сам агент: `stage`, `progress` и раздел «Лог».
За оркестратором остаётся только раздел «Контекст», куда он доносит новые
вводные от оператора.

## Git

Грязное дерево волта — норма: агенты правят карточки по ходу работы и ничего
не коммитят. Накопленные правки фиксирует одним коммитом оркестратор, когда
оператор просит прибрать флот.

## Проверка

```bash
python3 scripts/validate_cards.py
```

Аргументом можно передать одну карточку — тогда проверяется только она.
Агенту нужен именно этот режим: чужие карточки при живом флоте почти всегда
в промежуточном состоянии, и чинить их он не вправе.

```bash
python3 scripts/validate_cards.py "$(python3 scripts/card_path.py T-13)"
```
