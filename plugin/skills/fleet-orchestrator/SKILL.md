# Оркестрация флота

Ты диспетчер. Твоя работа — завести карточку, запустить агента, запинить его и
**остановиться**. Работу за агентов ты не делаешь и за ними не подглядываешь.

## Где доска

Доска лежит в каталоге флота, рядом с `docs`. Ниже каталог доски обозначен `<доска>`: подставляй его полный путь, в промпты агентам — тоже.

Как её найти — по порядку, до первого сработавшего:

- тебя назначил мастер пульта — доска названа в начале файла порядка работы, который он тебе прислал; дальше искать нечего;
- иначе — подкаталог твоего собственного рабочего каталога, в котором есть `cards` (обычно `board`): мастер поднимает оркестратора в каталоге флота, то есть прямо над доской;
- иначе — **спроси оператора**, какого ты флота, и ничего не заводи до ответа.

Гадать по `~/.config/fleetdeck/config.yaml` не надо, даже когда флот там один. Пульт мог быть запущен с другой конфигурацией — со стенда, из дев-сборки, с `-config`, — и тогда твоего флота там нет, зато есть чужой, и он выглядит убедительно. Флот, выбранный в пульте, тоже не ответ: это выбор вкладки оператора, и он меняется, пока ты работаешь. Карточка, заведённая не на той доске, теряется молча: её никто не увидит.

Сессия попадает во флот через поле `session` карточки на его доске. Пока ты его не вписал, пульт показывает сессию в группе «Без флота» — поэтому шаг 3 диспатча не откладывай.

## Диспатч задачи

1. Заведи карточку **только скриптом доски**:

   ```bash
   python3 <доска>/scripts/new_card.py \
     --title "Заголовок задачи" \
     --slug short-slug \
     --zone planned \
     --repo opensource/example
   ```

   Скрипт печатает путь заведённой карточки, проставляет `stage: new`, `progress: 0` и захватывает номер карточки в реестре `.ids/`. Руками карточку не создавай: номер останется незахваченным, и валидатор такую карточку отвергнет. Дальше допиши в неё раздел «Контекст».
2. Подними сессию через `create_session` **без промпта**: рабочий каталог —
   репозиторий задачи, имя — короткое и узнаваемое. Сессия встаёт и ждёт.
3. Впиши полученный short id в поле `session` карточки — и только после этого
   отправь задачу через `submit_prompt` по шаблону промпта ниже.
4. Запинь сессию через `pin_session`.
5. **Остановись и отчитайся оператору о том, что запущено.**

Шаги 2 и 3 местами не меняй и промпт в `create_session` не передавай. Иначе
агент стартует мгновенно и начинает править ту же карточку, в которой `session`
ещё не записан: твоя запись разъедется с его копией файла и потеряется молча.
`session` — единственное поле, связывающее карточку с сессией.

Перевод карточки в `stage: active` и `progress: 10` — работа самого агента, не
твоя. Граница ответственности проходит ровно по спавну.

Диспатчь **только тулами MCP** `claude-agents`. Не подменяй `submit_prompt`
межсессионным сообщением: такое сообщение придерживается до ручного
подтверждения оператора, и диспатч встаёт, пока человек его не одобрит.
`submit_prompt` печатает прямо в сессию и подтверждения не требует.

У сессии два разных идентификатора, не путай их. В поле `session` карточки идёт
**short id демона** — тот, что вернул `create_session`; его понимают
`get_session`, `read_screen` и `claude attach`. Имя и ссылка, под которыми та же
сессия видна в списке агентов, — другой адрес, и в карточке ему не место.

### Зона задачи

Поле `zone` задаёшь ты, и оно единственное выражает приоритет. Приоритет
убывает сверху вниз:

| Значение | Когда ставить |
| --- | --- |
| `urgent` | горит: продакшен лежит, блокер, срок сегодня |
| `unplanned` | прилетело внезапно, но делать надо в ближайшую очередь |
| `planned` | запланированная работа в обычном порядке |
| `niceToHave` | хорошо бы, но отложить можно без последствий |

Вид «В работе» группируется по `zone`, поэтому не сваливай всё в `urgent`:
доска перестанет различать срочное.

## Шаблон промпта агенту

Подставь номер карточки, каталог доски и постановку. Остальное оставь дословно.

```text
Твоя карточка на доске: T-NNN, доска <доска>. Путь резолвится по номеру:
python3 <доска>/scripts/card_path.py T-NNN — резолви его перед каждым
обращением к файлу, имя файла может измениться под тобой.

Веди её сам по скилу card-keeping: первым делом переведи в stage: active,
progress: 10, дальше обновляй прогресс по конвенции и дописывай находки в
раздел «Лог». Закончив, поставь stage: review — приёмка не твоя работа.

Постоянные правила:
- Свою ветку пушить можно и нужно: без запушенной ветки не бывает PR. Запрещено
  другое, и оно запрещено всегда: пуш в master, пуш с флагом принудительной
  перезаписи и создание тегов без слова оркестратора.
- Остальные публичные и наружные действия аппрувит оператор. Ты не открываешь и
  не комментируешь PR, ничего не публикуешь и никому не пишешь наружу без явного
  разрешения. Готовый результат возвращаешь на ревью.
- Разбор, который переживёт сессию, запрошен этой постановкой. Правило про
  непрошеную документацию к нему не относится: положи файл под docs доски и
  сошлись на него из карточки ссылкой `[[имя-файла]]` — путём текстом валидатор
  его не примет. Не написать разбор — молчаливый отказ, его никто не заметит.
- Попроси сессию начать фронтматтер разбора строкой `session: <её короткий id>`: панель откроет автора рядом с документом, и ответ на вопрос из разбора придёт ему.
- Аттрибуция Claude запрещена везде: ни в коммитах, ни в PR, ни в файлах, ни
  ссылкой на сессию.
- Любая команда kubectl вызывается с явным флагом --context. Общий kubeconfig
  переключают параллельные сессии, поэтому текущий контекст ничего не гарантирует.
- Упёрся в запрос разрешения, которого некому дать, или во внешнюю блокировку —
  ставь в карточке stage: blocked и пиши причину строкой в раздел «Лог». Молча
  висеть нельзя: пока причина не на доске, о ней никто не знает.
- Команду, способную ждать человека или сеть, запускай с ограничением по времени (timeout 60 ...): пока вызов не вернулся, ты заперт внутри него и не можешь ни поправить карточку, ни сообщить о своей остановке. Упёршись, сначала переводи карточку в blocked, потом жди. Защиту, в которую упёрся, обходить нельзя — подпись коммита в том числе.

Задача:
<ПОСТАНОВКА>
```

## Hand off: не нянчить

После диспатча ты **останавливаешься**. Запрещено:

- ставить таймеры и циклы ожидания, чтобы проверять агентов;
- читать транскрипты и экраны работающих сессий по собственной инициативе;
- пересказывать оператору результаты чужой работы.

Опрос флота — работа оператора. Он смотрит доску и при желании заходит в любую
сессию сам через `claude attach <short>`.

Единственное исключение: новую вводную от оператора донеси до работающего
агента — допиши её в раздел «Контекст» карточки и при необходимости отправь
`submit_prompt`. Это уточнение задачи, а не присмотр.

Владение карточкой меняется в момент спавна. **До** спавна frontmatter твой:
`zone`, `created`, `repo` заполняешь ты, `session` — тоже ты, и это последнее,
что ты в нём пишешь. **После** спавна frontmatter и раздел «Лог» принадлежат
агенту: он их ведёт и правит. Твоя половина файла с этого момента — только
раздел «Контекст».

`read_screen` применяй только тогда, когда оператор явно попросил заглянуть в
сессию.

## Развёртывание доски на новой машине

Доски нет — её разворачивает пульт, а не ты руками:

```bash
fleetdeck init
```

Команда создаёт конфигурацию пульта, ставит launchd-агент и раскладывает
доску из шаблона плагина, если её ещё нет. Отдельного файла видов у доски
больше нет: срезы «в работе», «на ревью» и «всё» рисует пульт, читая карточки.

Одного шага команда за оператора не сделает: разрешить агентам писать в
каталог доски. Путь надо добавить в `permissions.additionalDirectories`
в `~/.claude/settings.json` и перезапустить Claude Code. Без этого агент не
сможет вести свою карточку: доска лежит вне его рабочего каталога.

Доска — **разовая копия** шаблона. Обновление плагина обновляет скилы, но
доску не трогает: если шаблон с тех пор изменился, подтяни изменения.

```bash
${CLAUDE_PLUGIN_ROOT}/scripts/upgrade-board.sh
```

Скрипт добавляет недостающие файлы и обновляет каноничные скрипты из
`scripts/`. Про остальные разошедшиеся файлы он только сообщает: README и
правила оператор мог менять под себя. Повторный запуск безопасен.

Посмотреть, что разошлось, ничего не меняя:

```bash
${CLAUDE_PLUGIN_ROOT}/scripts/upgrade-board.sh --dry-run
```

Тот же отчёт, ни одной записи на диск, код возврата всегда нулевой.

Отдельной строкой скрипт называет скрипты, которые есть в `scripts/` доски и которых нет в шаблоне. Это расхождение в обратную сторону — не «доска отстала», а «доска ушла вперёд плагина», — и чинится оно не здесь, а в репозитории плагина: на живой доске вырастают скрипты, которые обязаны вернуться в шаблон, иначе доска, развёрнутая из шаблона, окажется не такой, как ваша. Сверяются только имена: содержимым живая доска расходится с шаблоном законно, и проверка по содержимому срабатывала бы всегда, а срабатывающую всегда проверку начинают пролистывать.

Доска у каждой машины своя. Поле `session` указывает на short id локального
демона, и на другом компьютере он не резолвится — общая доска дала бы смесь
двух флотов с мёртвыми ссылками.

## Гочи окружения

**Подкоманды CLI вызывай полным путём.** В `~/.zshrc` живёт алиас
`claude='claude --allow-dangerously-skip-permissions'`. Из-за него
`claude logs <short>` разворачивается в `claude --allow-dangerously-skip-permissions
logs <short>`, и `logs <short>` разбирается уже не как подкоманда, а как
**промпт**: вместо вывода сессии ты порождаешь новую одноразовую сессию,
которая отвечает на слово «logs». То же с `stop`. Обходится полным путём:
`/opt/homebrew/bin/claude logs <short>`.

**`claude agents --json` показывает не всё.** Без `--all` в выдаче нет части
сессий, в том числе только что поднятых. Полная картина — с `--all` либо через
`list_sessions` из MCP.

**Из песочницы состояние сессий читается неверно.** Песочница Bash режет
unix-сокеты, а значит и путь к демону. `claude agents --json`, вызванный
изнутри, показывал `failed` у сессий, которые на самом деле были `working` и
`blocked`; `claude logs` в тех же условиях отдаёт `ECONNREFUSED` на
`control.sock`, хотя демон жив и сокет слушает. Никогда не принимай решений
об уборке или перезапуске по такой выдаче: сначала перепроверь без песочницы
или через MCP.

**Состояние сессии называется по-разному** в разных источниках: список агентов
может показывать `waiting` там, где `claude agents --json --all` показывает
`working`. Доверяй MCP: он ходит в сокет демона напрямую.

## Пины

Пин означает «эта работа активна прямо сейчас».

- Пинь через `pin_session` сразу после спавна или воскрешения.
- Снимай пин тем же `pin_session` с `pinned=false`.
- Момент снятия ты не вычисляешь сам: перехода карточки в `review` ты не
  видишь, потому что доску не опрашиваешь. Триггер — слово оператора: работа
  принята либо пора прибрать флот. Поэтому снятие пинов входит в уборку.
- Поле `pinned` видно только через `list_sessions`. Пины слетают, когда сессия
  перестаёт быть живой, поэтому воскрешённые сессии перепинивай.

## Сверка доски с флотом

Запускается **только по просьбе оператора**. Сам не сверяй: это опрос флота,
а он запрещён разделом про hand off.

Зачем нужна. Доска знает, что агент сказал. Демон знает, жив ли он. Соединять
их — единственный способ поймать расхождение, и по построению никто, кроме
оператора, этого не делает. Самое опасное расхождение: сессия умерла, а
карточка навсегда осталась в `active`, и по доске всё выглядит работающим.

Как сверять:

1. Прочитай карточки в `<доска>/cards/`, возьми из каждой `stage`,
   `progress` и `session`.
2. Возьми `list_sessions`.
3. Сопоставь по `session` и доложи только расхождения.

Что считать расхождением:

| Карточка | Сессия | Что это значит |
| --- | --- | --- |
| `active` или `new` | нет в списке, `failed` или `done` | агент умер или закончил молча, карточка врёт |
| `review` или `done` | живая и работает | агент не остановился либо стадию поставили рано |
| `blocked` | живая и работает | блокировка снята, а стадию не вернули |
| `session` пусто, стадия не `new` | — | карточка потеряла связь с сессией |
| нет карточки | живая запиненная сессия | работа идёт мимо доски |

Докладывай расхождения списком и **ничего не чини молча**. Что с ними делать —
решает оператор: воскресить сессию, перевести карточку, прибрать или завести
недостающую карточку. Единственное, что делаешь сам, — предлагаешь по каждому
расхождению наиболее вероятное действие.

Если сверка запущена в сессии с включённой песочницей Bash, состояние сессий
читается неверно (см. раздел про гочи окружения). Перепроверь вне песочницы
или через MCP, прежде чем докладывать, что агент умер.

## Уборка

Уборку инициирует оператор. Убирай только завершённые сессии, чей результат
уже отдан и принят.

**Карточку, которую оператор перевёл в `done` в пульте, пульт уже прибрал.** Он снимает пин, читает последние слова сессии из её транскрипта, пишет строку в архив с ними и путём к транскрипту и потом мягко гасит сессию — те же четыре шага, что 1–4 ниже, в том же порядке, и останавливается на первом неудачном, а не гасит сессию, которую не смог записать. Для таких сессий делай только шаги 5 и 6: повтор 1–4 запишет вторую строку архива о сессии, которой уже нет.

Строка архива от пульта несёт только последний ответ сессии: то, что переживает сессию, из транскрипта пульт не достаёт, а именно для этого нужен шаг 2. Прогон, который стоит разобрать, по-прежнему стоит разобрать — транскрипт назван в строке, и `permanent=true` его не удаляет.

Целиком на тебе остаются: сессия без карточки, карточка, чью сессию пульт погасить не смог (его отчёт об этом говорит, а карточка остаётся в `done`), и любая уборка, которую оператор просит без перевода карточки.

1. Сними пины с этих сессий: `pin_session` с `pinned=false`.
2. **Добудь знание, пока сессия ещё существует.** Прогони по каждой:

   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/scripts/transcript_digest.py <short id>
   ```

   Скрипт выжимает из транскрипта реплики, ответы и список команд без их
   вывода — двенадцать мегабайт превращаются в неполный мегабайт. Ищи то,
   что переживёт сессию: расхождения документации с реальностью, грабли,
   выясненные последовательности действий, решения вместе с причинами.
   Найденное оформляется скилом, субагентом, записью в память или
   документом. Пустой результат — нормальный ответ, выдумывать находки
   ради находок не надо.

   Порядок здесь важен: чтение транскриптов распараллеливается по сессиям,
   а сочинение артефактов — нет, иначе получится несколько пересекающихся
   скилов про одно и то же.

3. Запиши строку в `<доска>/archive/AGENTS-ARCHIVE.md`: дата,
   short id, имя, карточка, что осталось после сессии. Обязательно укажи
   путь к транскрипту: после `permanent=true` он остаётся единственным
   следом сессии.
4. По умолчанию — `delete_session` с `permanent=false`. Это graceful
   остановка: история сохраняется, сессия поднимается заново.

   Учти: **список флота от этого не худеет.** Остановленная сессия остаётся
   в реестре со статусом `done` — именно затем, чтобы её можно было поднять.
   Если оператор убирается ради того, чтобы список стал короче, `stop` этой
   цели не достигает, и надо честно ему это сказать.

5. `permanent=true` убирает запись из состояния демона, после чего
   `resume_session` уже не поможет. Применяй, когда знание из сессии уже
   добыто шагом 2, а результат отдан: транскрипт `jsonl` переживает снос и
   остаётся в `~/.claude/projects/`, поэтому история не теряется — теряется
   только удобное воскрешение. Для мусорных и тестовых сессий — сразу.
6. Зафиксируй доску одним коммитом:

   ```bash
   git -C <доска> add --all
   git -C <доска> commit --signoff --message "chore(board): правки карточек за прогон флота"
   ```

   Доску коммитишь только ты и только здесь. Агенты этого не делают:
   `commit.gpgsign` включён глобально, коммит просит PIN, и фоновая сессия на
   этом запросе повиснет без человека. Уборку же затевает оператор, то есть
   человек в этот момент за машиной. Между уборками дерево доски грязное, и
   это норма.

## Воскрешение

На просьбу «запусти снова» первым делом пробуй `resume_session`: он поднимает
остановленную сессию на месте, с той же историей и тем же идентификатором.
`fork_session` нужен только тогда, когда исходную сессию надо сохранить нетронутой.

Если сессия была снесена окончательно, её транскрипт всё ещё лежит в
`~/.claude/projects/`, и его можно скормить новой сессии.

## Чего не делать никогда

Переносить состояние сессии на доску. Живо ли, чем занято, запинено ли — это
знает демон. Карточка хранит только смысл работы. Два источника правды на одно
поле неизбежно расходятся.
