# fleetdeck

[English version](README.md)

fleetdeck задуман как единое локальное окно для флота фоновых сессий Claude Code: их живое состояние, канбан-доска работы, которую они делают, и заметки с документацией вокруг этой работы — всё в одном месте вместо того, чтобы быть разбросанным по терминалам и отдельному приложению для заметок.

## Зачем нужен fleetdeck

Флот фоновых сессий Claude Code упирается в одни и те же три проблемы, как только вырастает больше двух-трёх сессий:

- Сессия останавливается и ждёт человека, а этого никто не замечает вовремя. Один зафиксированный случай: три сессии простояли без дела два часа после того, как лимит использования, который их остановил, уже сбросился, — потому что ничего не показало эту остановку.
- Чтобы понять, что делает одна сессия, нужно читать её терминальный экран, где содержательный текст перемешан со спиннерами и обрывками перерисовки, оставшимися от терминального интерфейса.
- Доска в Obsidian, которая используется для отслеживания работы, рассчитана на заметки, а не на пульт управления. Она понятия не имеет, какие сессии живы, ждут или застряли.

Ответ fleetdeck — пульт, который следит за сессиями и доской вместе, и одно-единственное поле — `session` — которое связывает карточку доски с сессией, работающей над ней, никогда не копируя состояние сессии в саму карточку. Смотрите [`docs/ru/getting-started.md`](docs/ru/getting-started.md), почему это поле — единственная разрешённая связь.

## Статус

Этот репозиторий находится в активной разработке. На момент написания:

- Из исходников собираются два бинаря: `fleetdeck` — пульт, и `fleetdeck-status` — репортёр статусной строки (см. «Пакеты» ниже).
- Пульт работает и отвечает на `127.0.0.1:7777`: веб-интерфейс, стоящий за ним снимок состояния флота, его поток по WebSocket и маршруты, которые печатают в сессию и двигают карточку.
- Команда `fleetdeck init` существует. На машине без конфигурации она создаёт рабочую папку — по умолчанию `~/fleetdeck` — с пустой доской из шаблона `plugin/templates/board` и каталогом документации и записывает конфигурацию, которая называет оба. Она направляет `statusLine` в Claude Code на `fleetdeck-status` и добавляет рабочую папку в `permissions.additionalDirectories` Claude Code. Шаг, который перезаписал бы то, что вы настроили сами, отказывается и говорит, как поступить.
- Пульт без файла конфигурации вместо доски показывает страницу настройки: она делает то же, что `init`, для папки, выбранной на странице — в приложении через системный диалог выбора папки, — и затем становится пультом.
- Кнопка доски **+ карточка** начинает карточку по заголовку и зоне.
- Приложение fleetdeck собирается командой `make window-app` в `bin/fleetdeck.app`: нативное окно вокруг пульта, которое носит пульт внутри бандла. Оно запускает пульт, когда никто не отвечает, и запускает снова, когда тот остановился; запущенный им пульт живёт ровно столько, сколько приложение — спрятанное окно его не трогает, завершение или падение приложения его останавливает; лог пульта — `~/Library/Logs/fleetdeck.log`. В его шапке есть кнопка «Обновить»: она подтягивает клон исходников, собирает приложение рядом с установленным и даёт новой версии встать на место, когда её пульт ответит.
- Сборка из исходников работает (`make build`), и релиз по тегу тоже: пуш тега `v*` запускает `.github/workflows/release.yaml`, который тестирует, собирает архивы `darwin-arm64` и `darwin-amd64` через `make dist`, проверяет их и публикует как GitHub Release. См. «Установку» ниже.

Что существует и работает уже сегодня: пакеты Go, стоящие за пультом, — чтение и запись карточек доски, загрузка конфигурации, общение с control-сокетом демона Claude Code, чтение транскриптов сессий, чтение лимитов использования аккаунта и отправка уведомлений macOS, — бинарь пульта `fleetdeck`, который их собирает воедино, репортёр статусной строки `fleetdeck-status` и плагин Claude Code в `plugin/`. Каждый из них описан в разделе «Пакеты» ниже.

## Установка

Установить можно сборкой из исходников или из GitHub Release: пуш тега `v*` запускает workflow `release` (`.github/workflows/release.yaml`), который тестирует, собирает архивы `darwin-arm64` и `darwin-amd64` через `make dist`, проверяет их и публикует.

`make build` кладёт оба бинаря в `bin/`: `fleetdeck` — пульт, и `fleetdeck-status` — репортёр статусной строки. Держите их вместе: `init` ищет репортёр рядом с бинарём пульта и записывает найденный путь в настройки Claude Code.

Затем запустите `fleetdeck init` или откройте приложение и выберите рабочую папку на его странице настройки. `init` создаёт рабочую папку (по умолчанию `~/fleetdeck`, либо `--workspace <путь>`) с пустой доской и каталогом документации, записывает называющий их `~/.config/fleetdeck/config.yaml`, если файла нет, и подключает `fleetdeck-status` и рабочую папку в `~/.claude/settings.json`. Он печатает по строке на шаг, включая шаги, от которых отказался, и причину: статусную строку, настроенную вами, он не трогает без `--force`, а отказ одного шага не останавливает остальные. Launch-агента, записанного прежним `init`, он называет вместе с двумя командами, которые его снимают. Затем соберите приложение командой `make window-app` и откройте `bin/fleetdeck.app`: оно запустит пульт. Весь порядок действий описан в [`docs/ru/getting-started.md`](docs/ru/getting-started.md).

## Ограничения

- **Только macOS.** Две части этого проекта вызывают специфичные для macOS инструменты без запасного варианта: чтение OAuth-токена Anthropic из macOS Keychain (через утилиту командной строки `security`) и показ баннеров уведомлений (через `osascript`). Ни у того, ни у другого сегодня нет кроссплатформенного аналога в этой кодовой базе.
- **Только локальный демон.** fleetdeck общается с демоном Claude Code через его Unix domain control-сокет на локальной машине. Удалённого или сетевого режима нет.
- **Доске нужны git и python3.** История доски — это git-репозиторий, а валидатор карточек, который запускают агенты, — скрипт на Python. На Mac без Command Line Tools `/usr/bin/git` и `/usr/bin/python3` — заглушки, которые предлагают их установить. Доска создаётся и без них, но тогда пульт не может закоммитить свои правки карточек, а агенты — проверить свои карточки. `xcode-select --install` даёт и то и другое.
- **Читает файлы в домашнем каталоге пользователя.** А именно: элемент macOS Keychain, хранящий учётные данные OAuth Claude Code, любые markdown-файлы в настроенном пути доски вместе с git-репозиторием, который их содержит, и файлы транскриптов сессий, которые Claude Code пишет для каждой сессии.
- **Баннер — это не подтверждённая доставка.** Код опирается только на код возврата `osascript`, а нулевой код возврата означает, что команда выполнилась, а не то, что баннер появился: macOS молча гасит уведомления, если доступ не разрешён или включён режим фокусировки, а `osascript` всё равно завершается с нулевым кодом. Здесь ничто не проверяет доставку на экран, поскольку для этого пришлось бы читать недокументированную приватную базу данных. Поэтому баннер, который так и не появился, — не ошибка, которую fleetdeck может сообщить: то, чему стоит доверять, чтобы понять, ждёт ли что-то внимания, — это собственные счётчики пульта, которые от всего этого не зависят.
- **Страница разрешает инлайновые стили — ради одной библиотеки.** Content-Security-Policy пульта — это `'self'` везде, кроме `style-src`, где добавлено `'unsafe-inline'`: вендоренный xterm.js создаёт элементы `<style>` во время работы и заполняет их измеренным размером ячейки терминала и цветами темы, а в этой версии библиотеки нет опции nonce. Без этого ключевого слова терминал рисуется пропорциональным шрифтом и без цвета. `script-src` и `default-src` остаются `'self'`, поэтому разрешён подставленный внешний вид, а не подставленное поведение — см. комментарий к `contentSecurityPolicy` в `internal/server/static.go`.
- **Учётные данные касаются ровно одного адреса.** fleetdeck читает OAuth-токен Anthropic из macOS Keychain через утилиту командной строки `security` и отправляет его ровно на один узел, `api.anthropic.com`. Он никогда не логирует токен, никогда не пишет его на диск и никогда не передаёт его в браузер.

## Сборка и тестирование

Требуется Go 1.27 (см. `go.mod`) и, для линтинга, `golangci-lint` v2.13.2 в `PATH`.

```sh
make build    # every binary under cmd/* into bin/
make test     # go test ./... -race -count=1
make test-web # runs every *.test.js under web/ (the frontend; needs node, no npm)
make lint     # go vet, gofmt -l, golangci-lint run
```

`make test-web` запускает тесты фронтенда в собственном тест-раннере node. Он не входит в `make test`, который остаётся только про Go, чтобы в окружении без node всё равно проходила полная проверка Go; CI запускает оба. Никакого npm install и никаких зависимостей скачивать не нужно.

`make verify-ldflags` собирает и запускает единственный тест, который проверяет, что путь символа внедрения версии релизной сборки (`internal/version`) по-прежнему разрешается; он не входит в `make test`, потому что требует собственных `-ldflags`, и CI запускает его отдельным шагом.

О конфигурации см. [`docs/ru/configuration.md`](docs/ru/configuration.md).

## Пакеты

- `internal/buildinfo` — говорит, какая сборка пульта сейчас работает: хэш вшитого веб-интерфейса, путь к бинарю, коммит, из которого он собран, и время сборки. Страница сравнивает этот хэш с тем, с которым пришёл её собственный документ, — так она узнаёт, что пульт под ней заменили на отдающий другой интерфейс.
- `internal/board` — читает и пишет доску флота: markdown-карточки с YAML-фронтматтером. Пульт владеет ровно двумя полями карточки, `stage` и `progress`, и умеет начать карточку по заголовку и зоне; всё остальное принадлежит агентам. Помимо стандартной библиотеки зависит от `github.com/fsnotify/fsnotify` для наблюдения за каталогом доски и от `gopkg.in/yaml.v3` для фронтматтера.
- `internal/config` — загружает и сохраняет YAML-файл конфигурации, описанный в [`docs/ru/configuration.md`](docs/ru/configuration.md). Отсутствующий файл — это набор значений по умолчанию, а не сбой; повреждённый файл — сбой.
- `internal/daemon` — клиент Unix control-сокета демона: обнаружение, проверки владения/безопасности сокета и файла control-ключа, а также операции `ping`, `list`, `reply` и `attach` (чтение экрана / отправка клавиш). Полный протокол, который он реализует, задокументирован в [`docs/protocol/daemon-control-socket.md`](docs/protocol/daemon-control-socket.md) (только на английском) — прочитайте это в первую очередь, прежде чем менять что-либо в этом пакете.
- `internal/notify` — показывает баннеры macOS через `osascript`. Решение об уведомлении принимает пульт, а не браузер: пульт знает состояние, и баннер не должен зависеть от того, открыта ли случайно вкладка браузера.
- `internal/server` — отдаёт снимок пульта по HTTP и WebSocket и принимает четыре записи, которые выполняет пульт: текст в сессию, клавиши в сессию, одно поле одной карточки и отчёт репортёра статусной строки. Ещё он начинает карточку, а пульту без конфигурации вместо всего этого отдаёт поверхность настройки (`NewSetup`). Сам не выполняет ввод-вывод, кроме того соединения, на которое отвечает: каждый источник, который ему нужен, приходит как функция в структуре `Deps`, а заполняет эту структуру `cmd/fleetdeck`. Помимо стандартной библиотеки и пакетов `internal/board`, `internal/daemon` и `internal/state`, зависит от `github.com/coder/websocket`.
- `internal/supervisor` — держит пульт свежим и запущенным без терминала: находит git, go и make по абсолютному пути и запускает make в окружении, где его рецепты находят go (у приложения из Dock своего PATH нет); перематывает дерево исходников вперёд и словами отказывается трогать дерево на чужой ветке, с правками или со своими коммитами; запускает пульт прямым потомком окна в собственной сессии, чтобы сигналы окна до него не доходили; останавливает пульт, занявший порт, только если тот отвечает как пульт fleetdeck; не даёт идти двум обновлениям сразу. Его хранитель и делает приложение хозяином пульта: берёт пульт, уже отвечающий на адресе пульта, — запущенный из терминала или пульт другого, ещё открытого окна, — заменяет пульт, чьего окна уже нет, запускает свой, когда не отвечает никто, запускает снова, когда тот умер, — если только он не умер в первые десять секунд, — и говорит, почему пульт не запускается, показывая конец его лога. Обновление собирает приложение в стороне, а окно новой версии принимает пульт: останавливает пульт, держащий порт, кто бы его ни запустил, и одним системным вызовом ставит свой бандл на место, когда его пульт ответит своей сборкой. Без cgo, поэтому проверяется на всех ветках CI.
- `internal/state` — хранит тип снимка, из которого пульт будет отрисовываться, и правила, определяющие, какие переходы состояния заслуживают баннера. Сам не выполняет ввод-вывод: каждый источник поступает в него как обычное значение, поэтому правила проверяемы без демона, каталога доски или сети.
- `internal/transcript` — читает транскрипты сессий Claude Code с хвоста: находит `.jsonl`-файл сессии, выжимку из его самых недавних шагов разговора и даёт оценку заполненности контекстного окна на случай, если репортёр статусной строки не установлен. Это источник того, что сессия сделала; он никогда не сообщает, что сессия делает прямо сейчас.
- `internal/usage` — читает окна лимита частоты запросов аккаунта с эндпоинта использования OAuth Anthropic. OAuth-токен читается из macOS Keychain, отправляется только на этот эндпоинт, никогда не логируется и никогда не сохраняется.
- `internal/workspace` — создаёт рабочую папку: `board`, git-репозиторий, разложенный по шаблону доски, и `docs`. Доска появляется целиком или не появляется вовсе, а каталог доски, в котором уже есть файлы, не трогается никогда.
- `plugin/templates` — несёт шаблон доски (`plugin/templates/board`) внутри бинаря, чтобы новая доска получала тот же валидатор, README и архив без копии этого репозитория.
- `internal/version` — версия сборки, внедряемая на этапе линковки `make build`/`make verify-ldflags`; смотрите собственные тесты этого пакета, чтобы понять, как проверяется внедрение.
- `cmd/fleetdeck` — сам пульт: собирает все пакеты выше в одну работающую программу, опрашивает демон, следит за доской, поднимает те баннеры, которые оставлены включёнными в настройках, и отдаёт всю картину на `127.0.0.1`.
- `cmd/fleetdeck-status` — репортёр статусной строки. Claude Code запускает его для каждой сессии: он печатает статусную строку и, по мере возможности, пересылает те же данные локальному пульту по HTTP, у которого нет другого способа их получить.

`internal/daemon` и `internal/transcript` используют только стандартную библиотеку. `internal/config` и `internal/board` также зависят от `gopkg.in/yaml.v3`, а `internal/board` дополнительно зависит от `fsnotify`. `internal/server` — единственный пакет, который знает о веб-сервере: помимо стандартной библиотеки и пакетов `internal/board`, `internal/daemon` и `internal/state`, он зависит от `github.com/coder/websocket`.
